You put marketing work into the project tool so the project holds the whole story — brief,
evidence, copy, reviewers, design request — before anyone reviews anything.

## Where the project tool is

The `house-rules` skill, Part 3.3.

**Pattern, not a promise.** If the project tool isn't connected, produce the same structure as
a list the requester can paste in, and say so. Every rule below still applies.

## When

**After the copy is settled — not before.** A project created at the first draft fills with
tasks nobody has agreed to.

## Find the home first

| Situation | Do |
|---|---|
| A campaign that exists | Find its project; add this asset to it |
| Named something you can't find | **Report what you did find and stop.** Never guess |
| Genuinely new | Create a **campaign** project, not an asset project |

Campaign projects, not asset projects — assets keep arriving, and the next one should land in
the same place.

## What the project holds

```
[Campaign name]
├── Brief            what was asked, the answers
├── Evidence         what the sources returned, with document names
├── Copy — [asset]   a LINK to the one document. Never pasted text
├── Review — [name]  owned by the reviewer, with a date
├── Design request   approved copy, approvals, layout intent, imagery brief
└── Back to library  the shipped asset, named
```

## Review tasks

| You were given | Do |
|---|---|
| A reviewer's name | Task owned by **that person**, with a due date |
| Several | One task each, in parallel unless one genuinely blocks another |
| No name | Create it **unassigned** and say the requester must find a reviewer |

**Never assign a review to the writer.** That's the mistake that leaves work sitting for weeks:
the writer stays owner and no reviewer is ever blocked.

**Name tasks as decisions:** *"Approve — [asset]"*, never *"Present copy to [name]"*.

**Every task has a date.** No date, no queue position. If nobody knows it, write
*"date TBC — requester to confirm"* — never invent one.

## Rules

- **Supply complete data; don't build routing rules** your project tool or team already owns.
- **Never guess** an existing project.
- **Links, not pasted copy.**

## Return exactly this

```
PROJECT     [name] — [created | found | not connected: list below]
TASKS       [name] → [owner] · due [date]
            …
OPEN        [anything missing: reviewer, date, folder]
```
